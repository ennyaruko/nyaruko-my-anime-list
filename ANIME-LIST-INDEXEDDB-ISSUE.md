# Почему список аниме ждал сеть вместо IndexedDB

## Причина

Список уже был сохранён в IndexedDB. После восстановления TanStack Query удалял его из оперативного кэша из-за слишком длинного `gcTime`: браузерный `setTimeout` переполнял задержку больше примерно 24,8 дня. Страница теряла восстановленный query и показывала состояние ожидания нового запроса к AniList.

Последовательность была такой:

```text
IndexedDB содержит список
        ↓
PersistQueryClientProvider восстанавливает QueryCache
        ↓
таймер gcTime переполняется и удаляет неактивный query
        ↓
useQuery больше не находит восстановленные данные
        ↓
страница ждёт сетевое обновление
```

Проверка в браузере подтвердила, что IndexedDB возвращала 302 записи, а ожидание появлялось после восстановления данных.

## Решение

`gcTime` и snapshot `maxAge` равны 24 дням. Это ниже предела браузерного таймера и выполняет требование ADR-004/005: `gcTime` не меньше `maxAge`. Это общий срок оболочки snapshot, а не отдельных query. Category-aware retention остаётся отдельной: список и справочные данные хранятся до 90 дней, детали аниме — до 30 дней. На восстановлении persister проверяет возраст каждой query и обновляет только timestamp оболочки; `dataUpdatedAt` не меняется.

Страница использует обычный `useQuery` и канонический ключ из query key factory. ID берётся из активной auth-сессии или ответа account query; это не позволяет выбрать владельца из произвольного старого user cache. Если ID уже сохранён в текущей auth-сессии, список подписывается на восстановленный query; stale data обновляется в фоне.

## Границы ответственности

- `src/shared/lib/persistence/category-aware-query-persister.ts` фильтрует сохранённые запросы по общей политике срока хранения и не интерпретирует формат данных AniList.
- `src/shared/lib/persistence/query-persistence-policy.ts` задаёт срок хранения по категориям query key.
- `src/app/providers/QueryProvider.tsx` подключает общий persister и задаёт версию снимка. После изменения формата версия увеличена до `v3`, поэтому старый несовместимый снимок будет отброшен, а не мигрирован.
- `src/shared/api/config/query-client.ts` задаёт общий `gcTime`, равный максимальному persisted сроку.
- `src/app/routes/anime.tsx` отображает данные через обычный `useQuery`; отдельного хука или ручного чтения списка из кэша нет.

Старый снимок не конвертируется: после завершения правок его можно удалить, а приложение создаст новый кэш в актуальном формате.

## Поведение

- При валидном кэше список становится доступен из IndexedDB после локального восстановления, не ожидая ответа AniList.
- Если данные устарели, сетевой запрос обновляет уже отображаемый список.
- Если сохранённого списка нет или его срок истёк, первый показ зависит от сети.
- Запросы сохраняются только в успешном состоянии. Явная кнопка обновления показывает отдельное состояние загрузки.
- Долгий `gcTime` и отдельный provider таймеров не используются.

## Проверка

Ранее браузерная проверка показала 302 восстановленные записи без ожидания сети. Текущий сценарий после этих изменений визуально не проверен. `npm run typecheck`, Prettier и ESLint для изменённых файлов прошли. `npm run locales:lint` не запустился: в окружении отсутствует нативный SWC binding и нет доступа к каталогу его кэша.
