## Цель

Создать простой и быстрый аниме-трекер, который позволяет пользователю:

- быстро найти аниме;
- открыть карточку;
- добавить в свой список.

Без лишних действий и перегруженного интерфейса.

**Контекст:**  
Существующие решения перегружены UI, имеют неудобный мобильный опыт и зависят от региональных ограничений.

## Целевая аудитория

- Пользователи, уже знакомые с аниме-трекерами.
- Используют существующие сервисы, но недовольны UX.
- Хотят более быстрый и простой инструмент.

## Scope MVP

### MUST

- Поиск аниме.
- Просмотр карточки аниме.
- Добавление в список (`watching` / `planned` / `completed` / `paused` / `dropped`).
- Просмотр своего списка.
- Синхронизация с внешним API.

### SHOULD

- Базовые фильтры (жанр, теги, статус, формат и первоисточник).
- Предустановленные категории.

## Критерии успеха (Lean)

| Цель                                                            | Метрика                                                                                                                                                              |
| --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Улучшить пользовательский опыт (UI/UX) по сравнению с аналогами | Сокращение количества кликов (User Steps) от открытия приложения до перехода в карточку детализации аниме (в пределах 1–2 кликов).                                   |
| Решить проблему региональных блокировок контента                | Доля успешно загружаемых тайтлов и постеров из международных баз данных составляет 100% в RU-регионе.                                                                |
| Оптимизировать процесс поиска через преднастроенные фильтры     | Наличие базовых фильтров с предустановленными значениями по умолчанию (на основе популярных паттернов пользователей), сокращающих время первичного подбора контента. |
| Обеспечить сохранность пользовательских списков                 | Синхронизация выполняется через AniList API. При ошибках API пользователь получает уведомление, повторные попытки не гарантируются.                                  |

## Предположения и ограничения

### Пользовательские предположения

Пользователи в RU-регионе испытывают дискомфорт из-за блокировок популярных тайтлов на локальных ресурсах, перегруженных рекламой интерфейсов аналогов и неудобных мобильных интерфейсов. Предполагается, что они готовы использовать новый аниме-лист ради чистого UI/UX, удобной базовой фильтрации и независимости от региональных ограничений.

### Технические ограничения и зависимость от внешнего API

- На этапе MVP приложение полностью полагается на единую внешнюю базу данных (например, AniList API). Полнота каталога тайтлов, доступность метаданных (включая контент категорий Ecchi/R+) и скорость фильтрации контента напрямую ограничены возможностями и стабильностью выбранного стороннего API.
- Для полноценной работы со списками и синхронизацией пользователь обязан иметь аккаунт AniList. Без него функциональность трекинга и сохранения списков недоступна.
- Все данные в AniList ведутся на английском языке, приложение должно переводить и предоставлять пользователям контент на русском языке.

### Политика конфиденциальности и локальное хранение данных

На этапе MVP в приложении отсутствует сбор аналитики, метрик активности пользователей или их предпочтений на стороне системы. Вся информация о списках пользователя синхронизируется напрямую с его личным профилем на стороне внешнего API.

### Границы продукта

Приложение проектируется строго как персональный трекер-каталог (аниме-лист). В MVP полностью отсутствуют интеграции медиаплееров, ссылки на сторонние онлайн-кинотеатры или логика просмотра видеоконтента.

### Бизнес-предположения

Проект разрабатывается как пет-проект, коммерческая монетизация на этапе MVP отсутствует. Главной ценностью релиза является проверка продуктовых гипотез вокруг UI/UX и создание стабильного интерфейса для личного использования.

## Вне области

Спорные функциональности вне определённых требований или функциональности, которые могут быть реализованы позднее.

- **Встроенные плееры и парсеры сайтов просмотра:**  
  Приложение выполняет исключительно функцию трекера и каталога. В MVP полностью отсутствует логика интеграции видеоплееров или парсинга внешних стриминговых сайтов.

- **Кастомные коллекции:**  
  Создание своих коллекций вне рамках релиза MVP.

- **Собственные пресеты фильтров:**  
  Возможность для пользователя создавать, сохранять и именовать свои собственные шаблоны фильтрации («Мой кастомный фильтр 2026») перенесена на следующие фазы. В MVP доступны только системные пресеты.

- **Система аналитики и AI-рекомендации:**  
  Локальный сбор статистики просмотров и использование нейросетей для генерации персональных рекомендаций полностью исключены из первой фазы.

- **Функция «Случайное аниме» (Рандомайзер):**  
  Кнопка быстрой выдачи случайного тайтла (как обычная, так и с учётом предпочтений пользователя) полностью перенесена на следующие итерации разработки.

- **Фильтрация по контенту по умолчанию и “Adult контент / 18+”:**  
  Интеграция сторонних альтернативных баз данных ради расширения каталога NSFW-контента (который может отсутствовать в AniList) не реализуется в MVP. В первой версии фильтрация Adult-контента опирается исключительно на стандартные возможности базового API.
